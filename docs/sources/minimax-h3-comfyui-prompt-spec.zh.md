# MiniMax-H3 ComfyUI Prompt Generator

## Skill Name

`minimax-h3-comfyui-prompt-generator`

## Description

根据用户提供的人物、参考图、场景、剧情、对白、镜头和声音要求，生成适用于 MiniMax-H3 / ComfyUI 的结构化视频提示词。

核心原则：

> **不改变固定提示词语法，只替换人物、场景、剧情、对白、镜头动作和声音内容。**

固定语法结构：

```text
<Subject> / S / [Shot] / says / <d>
```

---

## 1. 输入信息

Skill 可以接受以下信息：

### 人物

- 人物名称
- 人物编号
- 参考图片
- 人物在参考图中的位置
- 面部特征
- 发型
- 服装
- 身材比例
- 道具
- 整体外貌

### 声音

- 性别
- 年龄感
- 音域
- 音色
- 常态语速
- 音量
- 句尾特征
- 不同情绪下的声音变化
- 禁止的声音风格

### 场景

- 地点
- 时间
- 天气
- 光线
- 背景
- 环境物体
- 环境声音

### 人物关系

- 左右位置
- 人物距离
- 身体朝向
- 视线关系
- 手部状态
- 道具状态
- 人物之间的空间关系

### 剧情

- 故事梗概
- 角色行为
- 情绪变化
- 对白
- 结局动作

### 分镜

如果用户没有提供具体分镜，Skill 自动将剧情拆分成合理的 Shot。

每个 Shot 应包含：

1. 景别
2. 机位 / 构图
3. 人物动作
4. 微动作
5. 表情
6. 情绪
7. 前景 / 背景关系
8. 道具状态
9. 对白（如果有）

---

# 2. 固定人物结构

每个主要人物必须使用 `<SubjectX>` 绑定。

格式：

```text
<Subject1>[人物名称]是<Picture 1>画面[位置]人物，
保留参考图中的[面部特征]、[发型]、[服装]、
[身材比例]、[道具]以及整体外貌。
```

例如：

```text
<Subject1> Gu Yan是<Picture 1>画面左侧男性，保留参考图中的面部特征、黑色短发、黑色西装、白色衬衫、身材比例以及整体外貌。
```

要求：

- 不随意改变人物编号。
- 不随意交换人物左右位置。
- 用户提供参考图时，优先使用参考图中的视觉特征。
- 人物的服装、发型、道具应在整个视频中保持一致，除非剧情明确改变。

---

# 3. 固定声音结构

每个说话人物必须绑定唯一的 `S` 编号。

格式：

```text
<Subject1>，S1 永远是说话人。
S1始终使用一种固定的声音：
[年龄感]，[性别]，[音域]，
音色[音色描述]，
常态语速[语速]、音量[音量]，
[句尾特征]；
[情绪状态1]；
[情绪状态2]；
[情绪状态3]。
禁止[声音风格1]、[声音风格2]、[声音风格3]。
```

例如：

```text
<Subject1>，S1 永远是说话人。S1始终使用一种固定的声音：20岁出头男性，中低音，音色干净沉稳，常态语速中等、音量偏低，句尾利落下收；说冷笑话时语气保持认真，只在最后几个字稍微放松；被拆穿后呼吸略微松开，声音中带一点压住的笑意。禁止播音腔、霸总气泡音、夸张精英腔和故作深沉。
```

## 声音设计规则

声音描述必须同时包含：

### 固定属性

- 年龄感
- 性别
- 音域
- 音色
- 语速
- 音量
- 句尾

### 动态属性

根据剧情设置：

- 正常
- 紧张
- 怀疑
- 开心
- 生气
- 尴尬
- 被拆穿
- 放松
- 开玩笑
- 犹豫
- 惊讶

### 禁止属性

必须明确禁止容易导致声音跑偏的风格。

例如：

```text
禁止夹子音、幼态撒娇腔、尖叫和播音腔。
```

---

# 4. 场景结构

场景统一使用：

```text
<Subject3>是[场景描述]。

人物站位：
[人物1的位置、朝向、手部状态]；
[人物2的位置、朝向、手部状态]。

两人[距离关系]。
[背景主要物体及位置]。
保持两人的左右关系与视线轴线。
[环境声音]。
```

必须优先锁定：

- 人物左右关系
- 人物前后关系
- 人物之间距离
- 身体朝向
- 视线轴线
- 主要道具位置
- 背景主要物体
- 环境声音

---

# 5. Shot 结构

每个镜头必须使用：

```text
[Shot 1]
[镜头类型 / 景别 / 机位 / 构图]。
[人物动作1]，[人物动作2]，[人物动作3]。
[表情 / 微表情 / 情绪]。

<Subject X> (SX) says:
<d>[Chinese]对白</d>
```

无对白镜头：

```text
[Shot 3]
[镜头类型 / 景别 / 构图]。
[动作连续变化]。
[表情 / 微动作]。
```

不要强行为没有对白的镜头添加台词。

---

# 6. Shot 的动作写法

动作必须优先使用连续动作链，而不是简单动作列表。

推荐：

```text
先回头看向飞机，又立刻转回人物；
双手同时收紧；
身体微微前倾；
眼神带着怀疑。
```

不要写成：

```text
看飞机、转头、抓袋子、说话。
```

动作优先表现：

```text
动作A
→ 动作B
→ 动作C
→ 表情变化
→ 台词
```

---

# 7. 微动作规则

为了提高视频表演的连续性，每个关键 Shot 应尽可能包含适量微动作。

可使用：

- 手指收紧
- 握紧道具
- 松开道具
- 呼吸变化
- 肩膀放松
- 眼神移动
- 嘴唇张开
- 嘴唇闭合
- 眉毛变化
- 身体前倾
- 身体后仰
- 低头
- 抬头
- 踮脚
- 衣服褶皱
- 道具滑落
- 重新抓稳

避免无意义地堆砌微动作。

---

# 8. Shot 连续性

所有 Shot 必须形成连续的视频动作。

后续镜头默认继承之前建立的：

- 人物位置
- 人物左右关系
- 人物服装
- 人物发型
- 道具
- 道具状态
- 人物关系
- 环境
- 时间
- 光线
- 视线轴

例如：

```text
Shot 1：
人物握紧手提袋。

Shot 2：
手提袋仍然存在。

Shot 3：
手提袋从手腕滑落。

Shot 4：
人物重新抓稳手提袋。
```

不要在 Shot 4 中无理由让手提袋出现在另一只手。

---

# 9. 对白格式

所有对白严格使用：

```text
<Subject X> (SX) says:
<d>[Chinese]对白内容</d>
```

例如：

```text
<Subject 2> (S2) says:
<d>[Chinese]你不是说，订的是经济舱吗？</d>
```

规则：

- `Subject` 和 `S` 必须对应。
- S1 只能说 Subject1 的台词。
- S2 只能说 Subject2 的台词。
- 不允许出现未定义的说话人。
- 不允许把多个角色的对白写在同一个 `says` 中。
- 中文对白统一使用 `[Chinese]`。
- 不修改用户明确提供的台词含义。
- 如需润色对白，保持角色性格和声音设定。

---

# 10. 对白与动作同步

对白不能脱离动作。

优先结构：

```text
动作
→ 表情
→ 说话
```

或者：

```text
动作开始
→ 人物看向对方
→ 表情变化
→ 开口说话
→ 说完后的反应
```

例如：

```text
Gu Yan顺着她刚才的视线看向飞机，
抬手整理了一下袖口，
随后重新看向她，
表情认真得没有一丝玩笑：

<Subject 1> (S1) says:
<d>[Chinese]对啊，经济情况允许的舱。</d>
```

---

# 11. 镜头设计原则

根据剧情自动选择合理景别。

### 双人互动

优先：

```text
斜侧双人中景
正面双人中景
双人中近景
```

### 单人对白

优先：

```text
正面中近景
正面近景
斜侧近景
```

### 情绪反应

优先：

```text
正面近景
面部特写
```

### 道具 / 环境信息

优先：

```text
斜侧近景
局部特写
环境中景
```

镜头选择应服务于剧情，而不是为了增加镜头数量。

---

# 12. 镜头数量

根据剧情长度自动拆分。

默认原则：

- 一个明显的动作阶段 = 一个 Shot
- 一个明显的情绪转折 = 一个 Shot
- 一个新的视觉重点 = 一个 Shot
- 一段连续动作不要无意义切镜

如果用户指定 Shot 数量，严格遵守。

如果用户指定视频时长，应根据时长合理控制 Shot 数量和动作密度。

---

# 13. 全局禁止项

默认在提示词末尾加入：

```text
【禁止项】

文字/UI/水印/Logo/角标/可读文字/真实UI
```

如用户有额外禁止内容，追加到此区域。

例如：

```text
【禁止项】

文字/UI/水印/Logo/角标/可读文字/真实UI/
畸形手指/多余人物/人物身份漂移/服装变化
```

---

# 14. 强制声明

默认使用：

```text
【强制声明】

无背景音乐,仅保留环境音与人声和音效;
画面禁字幕/文字/水印/Logo;
禁止可读文字(指画面字幕文字,不含人声台词)
```

除非用户明确要求音乐，否则不得自动添加背景音乐。

---

# 17. 质量检查

输出前必须检查：

### 人物

- [ ] Subject 编号是否唯一
- [ ] 人物左右位置是否一致
- [ ] 外貌是否一致
- [ ] 服装是否一致
- [ ] 道具是否一致

### 声音

- [ ] 每个说话人物是否有唯一 S 编号
- [ ] Subject 与 S 是否对应
- [ ] 是否描述固定声音
- [ ] 是否描述情绪变化
- [ ] 是否包含声音禁止项

### 镜头

- [ ] 每个 Shot 是否有明确视觉内容
- [ ] 是否包含合理景别
- [ ] 动作是否具有先后关系
- [ ] 是否包含必要的微动作
- [ ] Shot 之间是否连续

### 对白

- [ ] 是否使用 `says`
- [ ] 是否使用 `<d>[Chinese]... </d>`
- [ ] 台词是否绑定正确人物
- [ ] 是否避免无意义旁白

### 全局约束

- [ ] 是否包含禁止项
- [ ] 是否禁止字幕
- [ ] 是否禁止 Logo / 水印
- [ ] 是否禁止可读文字
- [ ] 是否无背景音乐，除非用户明确要求

---

# 18. 重要行为规则

1. **不要擅自改变模板语法。**
2. **不要把 `<Subject>` 改成普通人物描述。**
3. **不要删除 S1/S2 等声音绑定。**
4. **不要把对白改成普通引号形式。**
5. **不要把多个 Shot 合并成一段剧情描述。**
6. **不要为了“文学性”牺牲动作执行的明确性。**
7. **不要随意添加用户没有要求的背景音乐。**
8. **不要自动添加字幕、UI、Logo 或屏幕文字。**
9. **优先保证人物、道具、空间和动作连续性。**
10. **用户提供的固定台词应尽量原样保留。**
11. **如果信息不足但可以合理推断，应采用最保守、最符合上下文的方案继续生成。**
12. **只有当缺失信息会严重影响人物身份、剧情逻辑或镜头执行时，才向用户询问。**

---

# 19. 最终目标

这个 Skill 的最终输出不是普通的“视频描述”，而是：

> **可直接用于 MiniMax-H3 / ComfyUI 工作流的结构化视频生成提示词。**

核心结构始终保持：

```text
Subject
↓
Voice / S
↓
Scene
↓
Spatial Continuity
↓
Shot Timeline
↓
Dialogue Binding
↓
Global Constraints
```

固定语法优先级：

```text
<SubjectX>
S X
[Shot X]
<Subject X> (SX) says:
<d>[Chinese]...</d>
```

剧情、人物、场景、对白、镜头、声音内容可以变化，但上述**结构和绑定关系必须保持稳定**。
